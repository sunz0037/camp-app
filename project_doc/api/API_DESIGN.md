# 校园OA系统API接口设计文档

## 一、接口设计规范

### 1.1 基础规范
- **协议**：HTTP/HTTPS
- **数据格式**：JSON
- **字符编码**：UTF-8
- **认证方式**：JWT Token（Bearer Token）

### 1.2 统一响应格式
```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": "2024-01-01T00:00:00"
}
```

### 1.3 HTTP状态码
- `200` - 成功
- `201` - 创建成功
- `400` - 请求参数错误
- `401` - 未授权
- `403` - 无权限
- `404` - 资源不存在
- `500` - 服务器错误

### 1.4 分页参数
```json
{
  "page": 1,
  "size": 20,
  "total": 100,
  "pages": 5
}
```

## 二、用户认证与授权接口

### 2.1 用户登录
- **接口路径**：`POST /api/auth/login`
- **功能说明**：用户登录，返回JWT Token
- **请求参数**：
```json
{
  "username": "string",
  "password": "string"
}
```
- **响应数据**：
```json
{
  "token": "string",
  "refreshToken": "string",
  "userInfo": {
    "id": 1,
    "username": "string",
    "realName": "string",
    "userType": 1
  }
}
```
- **权限要求**：无

### 2.2 用户登出
- **接口路径**：`POST /api/auth/logout`
- **功能说明**：用户登出，清除Token
- **权限要求**：已登录用户

### 2.3 刷新Token
- **接口路径**：`POST /api/auth/refresh`
- **功能说明**：刷新访问Token
- **请求参数**：
```json
{
  "refreshToken": "string"
}
```
- **权限要求**：已登录用户

### 2.4 获取当前用户信息
- **接口路径**：`GET /api/auth/me`
- **功能说明**：获取当前登录用户的详细信息
- **权限要求**：已登录用户

### 2.5 修改密码
- **接口路径**：`PUT /api/auth/password`
- **功能说明**：修改当前用户密码
- **请求参数**：
```json
{
  "oldPassword": "string",
  "newPassword": "string"
}
```
- **权限要求**：已登录用户

## 三、用户管理接口

### 3.1 创建用户
- **接口路径**：`POST /api/users`
- **功能说明**：创建新用户（学生、教职工、管理员）
- **请求参数**：
```json
{
  "username": "string",
  "password": "string",
  "realName": "string",
  "idCard": "string",
  "phone": "string",
  "email": "string",
  "userType": 1
}
```
- **权限要求**：系统管理员

### 3.2 查询用户列表
- **接口路径**：`GET /api/users`
- **功能说明**：分页查询用户列表
- **查询参数**：
  - `page`: 页码
  - `size`: 每页数量
  - `userType`: 用户类型（可选）
  - `keyword`: 关键词搜索（用户名、姓名）
- **权限要求**：系统管理员

### 3.3 查询用户详情
- **接口路径**：`GET /api/users/{id}`
- **功能说明**：根据ID查询用户详细信息
- **权限要求**：系统管理员 或 查询自己的信息

### 3.4 更新用户信息
- **接口路径**：`PUT /api/users/{id}`
- **功能说明**：更新用户信息
- **权限要求**：系统管理员 或 更新自己的信息

### 3.5 删除用户
- **接口路径**：`DELETE /api/users/{id}`
- **功能说明**：删除用户（软删除，更新状态）
- **权限要求**：系统管理员

### 3.6 启用/禁用用户
- **接口路径**：`PUT /api/users/{id}/status`
- **功能说明**：启用或禁用用户
- **请求参数**：
```json
{
  "status": 1
}
```
- **权限要求**：系统管理员

## 四、学生信息管理接口

### 4.1 创建学生信息
- **接口路径**：`POST /api/students`
- **功能说明**：创建学生信息记录
- **请求参数**：
```json
{
  "userId": 1,
  "studentNo": "string",
  "grade": "string",
  "className": "string",
  "major": "string",
  "department": "string",
  "enrollmentDate": "2024-01-01",
  "dormitory": "string",
  "address": "string",
  "gender": 1,
  "birthDate": "2024-01-01"
}
```
- **权限要求**：系统管理员

### 4.2 查询学生列表
- **接口路径**：`GET /api/students`
- **功能说明**：分页查询学生列表（根据权限自动过滤）
- **查询参数**：
  - `page`: 页码
  - `size`: 每页数量
  - `grade`: 年级（可选）
  - `className`: 班级（可选）
  - `major`: 专业（可选）
  - `keyword`: 关键词搜索（学号、姓名）
- **权限要求**：
  - 系统管理员：可查询全部
  - 年级管理员：仅可查询本年级
  - 教师：仅可查询本班级
  - 学生：仅可查询自己

### 4.3 查询学生详情
- **接口路径**：`GET /api/students/{id}`
- **功能说明**：根据ID查询学生详细信息
- **权限要求**：
  - 系统管理员：可查询全部
  - 年级管理员：仅可查询本年级学生
  - 教师：仅可查询本班级学生
  - 学生：仅可查询自己

### 4.4 更新学生信息
- **接口路径**：`PUT /api/students/{id}`
- **功能说明**：更新学生信息
- **权限要求**：系统管理员

### 4.5 删除学生信息
- **接口路径**：`DELETE /api/students/{id}`
- **功能说明**：删除学生信息（软删除）
- **权限要求**：系统管理员

### 4.6 批量导入学生
- **接口路径**：`POST /api/students/batch-import`
- **功能说明**：批量导入学生信息（Excel文件）
- **请求参数**：multipart/form-data（文件上传）
- **权限要求**：系统管理员

### 4.7 导出学生信息
- **接口路径**：`GET /api/students/export`
- **功能说明**：导出学生信息（Excel文件）
- **查询参数**：同查询学生列表
- **权限要求**：系统管理员（教师和年级管理员不可导出）

## 十六、接口权限说明

### 权限最小化原则实施

#### 数据查询权限自动过滤
- **教师角色**：查询学生、成绩、应急联系人时，系统自动JOIN `teacher_classes` 表，仅返回所管理班级的数据
- **年级管理员角色**：查询学生、成绩、应急联系人时，系统自动JOIN `grade_admin_grades` 表，仅返回所管理年级的数据
- **学生角色**：查询时自动添加 `student.user_id = current_user_id` 条件

#### 数据导出限制
- 教师和年级管理员角色默认禁止导出数据（`can_export = 0`）
- 系统管理员和后勤人员（针对来访登记）可以导出数据

#### 字段权限控制
- 通过 `field_permissions` 字段可限制可查询的字段
- 敏感字段（身份证号、家庭地址等）可通过此机制进行保护

## 十七、接口设计注意事项

1. **统一异常处理**：所有接口应统一处理异常，返回标准错误响应
2. **参数验证**：所有输入参数应进行验证，防止SQL注入、XSS等安全问题
3. **权限验证**：每个接口都应进行权限验证，确保用户只能访问有权限的数据
4. **日志记录**：重要操作（增删改）应记录操作日志
5. **数据脱敏**：返回数据时，根据权限对敏感字段进行脱敏处理
6. **分页限制**：分页查询应限制最大每页数量，防止大量数据查询
7. **缓存策略**：对频繁查询的数据（如公告列表）可考虑使用缓存
8. **接口版本控制**：建议使用 `/api/v1/` 前缀，便于后续版本升级

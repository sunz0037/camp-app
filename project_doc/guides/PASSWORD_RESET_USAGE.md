# 密码重置功能使用说明

## 一、功能概述

密码重置功能已实现，支持两种身份类型的重置方式：

1. **学生**：六要素验证重置
2. **教工**：手机验证码重置
3. **访客/家长**：暂不支持

## 二、学生密码重置

### 2.1 重置流程

1. 访问密码重置页面：`/reset-password`
2. 选择"学生"身份
3. 填写以下6项信息：
   - 学号
   - 真实姓名
   - 身份证号（18位）
   - 应急联系人姓名
   - 应急联系人电话（11位手机号）
   - 关系（父亲/母亲/监护人/其他）
4. 点击"重置密码"
5. 验证通过后，密码自动重置为**身份证号后6位**

### 2.2 验证规则

- 学号必须存在
- 学号与真实姓名必须匹配
- 身份证号必须与用户信息匹配
- 应急联系人信息（姓名+电话+关系）必须与学生关联的应急联系人匹配

### 2.3 重置后的密码

- 新密码：身份证号后6位
- 示例：身份证号 `110101200001011234` → 新密码 `011234`
- 使用BCrypt加密存储（强度5）

## 三、教工密码重置

### 3.1 重置流程

1. 访问密码重置页面：`/reset-password`
2. 选择"教工"身份
3. 填写以下信息：
   - 工号
   - 真实姓名
   - 手机号（11位）
4. 点击"发送验证码"
5. 输入收到的6位验证码
6. 点击"重置密码"
7. 验证通过后，密码自动重置为**身份证号后6位**

### 3.2 验证规则

- 工号必须存在
- 工号与真实姓名必须匹配
- 手机号必须与用户绑定的手机号匹配
- 验证码必须正确且在有效期内（5分钟）

### 3.3 验证码说明

- 验证码：6位数字
- 有效期：5分钟
- 发送频率：每次点击"发送验证码"后，60秒内不能再次发送
- 验证码只能使用一次

### 3.4 重置后的密码

- 新密码：身份证号后6位
- 使用BCrypt加密存储（强度5）

## 四、API接口

### 4.1 发送验证码（教工）

```
POST /api/auth/send-verification-code

请求体：
{
  "identityType": 2,
  "identifier": "T001",
  "realName": "李老师",
  "phone": "13900000001"
}

响应：
{
  "code": 200,
  "message": "success",
  "data": {
    "success": true,
    "message": "验证码已发送到手机",
    "maskedPhone": "****0001",
    "token": "token_xxx"
  }
}
```

### 4.2 重置密码

**学生重置：**
```
POST /api/auth/reset-password

请求体：
{
  "identityType": 1,
  "identifier": "20240001",
  "realName": "张三",
  "idCard": "110101200001011234",
  "contactName": "张父",
  "contactPhone": "13800000001",
  "relationship": "父亲"
}
```

**教工重置：**
```
POST /api/auth/reset-password

请求体：
{
  "identityType": 2,
  "identifier": "T001",
  "realName": "李老师",
  "phone": "13900000001",
  "verificationCode": "123456"
}
```

**响应：**
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "success": true,
    "message": "密码已重置为身份证号后6位，请使用新密码登录",
    "maskedIdCard": "****1234",
    "maskedPhone": "****0001"
  }
}
```

## 五、安全措施

### 5.1 频率限制

- 同一学号/工号，5分钟内最多尝试3次
- 超过3次后，锁定30分钟
- 错误信息：`验证失败次数过多，请30分钟后再试`

### 5.2 验证码安全

- 验证码有效期：5分钟
- 验证码只能使用一次
- 验证码错误5次后，需要重新发送

### 5.3 日志记录

所有重置操作都会记录到 `password_reset_logs` 表，包括：
- 用户ID（成功时）
- 学号/工号
- 身份类型
- 重置类型（1-学生六要素，2-教工手机验证码）
- 状态（0-失败，1-成功）
- 失败原因
- IP地址
- 用户代理
- 创建时间

## 六、错误提示

### 6.1 学生重置错误

| 错误信息 | 原因 |
|---------|------|
| 学号不存在 | 输入的学号在系统中不存在 |
| 真实姓名不匹配 | 学号与真实姓名不匹配 |
| 身份证号不匹配 | 身份证号与用户信息不匹配 |
| 应急联系人信息不匹配 | 应急联系人姓名/电话/关系不匹配 |
| 验证失败次数过多，请30分钟后再试 | 5分钟内尝试超过3次 |

### 6.2 教工重置错误

| 错误信息 | 原因 |
|---------|------|
| 工号不存在 | 输入的工号在系统中不存在 |
| 真实姓名不匹配 | 工号与真实姓名不匹配 |
| 手机号不匹配 | 手机号与用户绑定的手机号不匹配 |
| 验证码错误或已过期 | 验证码输入错误或超过5分钟有效期 |
| 用户未设置身份证号，无法重置密码 | 用户信息中没有身份证号 |
| 验证失败次数过多，请30分钟后再试 | 5分钟内尝试超过3次 |

## 七、注意事项

### 7.1 学生重置

1. **应急联系人信息**：确保学生已填写应急联系人信息
2. **身份证号**：必须是18位，且与用户信息中的身份证号完全匹配
3. **关系字段**：必须与数据库中存储的关系完全一致（父亲/母亲/监护人/其他）

### 7.2 教工重置

1. **手机号绑定**：确保教工已绑定手机号
2. **验证码接收**：当前使用内存存储验证码，实际生产环境需要集成短信服务
3. **身份证号**：教工必须设置身份证号才能重置密码

### 7.3 重置后的操作

1. **立即登录**：使用新密码（身份证号后6位）登录
2. **修改密码**：登录后建议立即修改密码，提高安全性
3. **密码保密**：身份证号后6位作为密码，注意保密

## 九、开发环境说明

### 9.1 验证码服务

当前使用**内存存储**验证码，适合开发测试：
- 验证码存储在内存中
- 服务重启后验证码失效
- 定时清理过期数据（每5分钟）

### 9.2 生产环境建议

1. **使用Redis存储验证码**：
   - 支持分布式部署
   - 数据持久化
   - 更好的性能

2. **集成短信服务**：
   - 阿里云短信服务
   - 腾讯云短信服务
   - 其他第三方短信服务

3. **监控和告警**：
   - 重置失败率监控
   - 异常IP检测
   - 频率限制告警

## 十、数据库表

### 10.1 password_reset_logs 表

表已创建，包含以下字段：
- `id` - 记录ID
- `user_id` - 用户ID（成功时）
- `identifier` - 学号/工号
- `identity_type` - 身份类型（1-学生，2-教工）
- `reset_type` - 重置类型（1-学生六要素，2-教工手机验证码）
- `status` - 状态（0-失败，1-成功）
- `failure_reason` - 失败原因
- `ip_address` - 请求IP
- `user_agent` - 用户代理
- `created_at` - 创建时间
